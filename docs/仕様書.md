# 仕様書

このツールの処理仕様（保守する人向け）。コーディング規約は comken リポジトリの
`docs/CONVENTIONS_COMMON.md`（入口）から辿る規約に従う。

---

## 1. 目的・概要

soql-collector が生成したレポート定義（`SoqlReport` のサブクラスを書いた `.py`）を、
ダウンローダーの `src/soql_reports/reports/` に入れる**前**に、1 本だけ実行して確かめる。

- 対象は読み取り専用。Salesforce への書き込み、管理表の書き換え、
  ダウンローダーへのファイル配置はしない
- 画面・ログには件数・列名・出力先・クラス名だけを出す。**行の値は出さない**

---

## 2. 処理フロー

```
  ↓
SOQL を得る（SoqlReport.soql()）
  ↓
先頭が未完成の印 → 接続せずに終了（コード 1）
  ↓
site_for(url) で接続 → bulk_query(soql)
  ↓
件数の比較（CHECK_COUNT が True のとき。レポート API の RowCount と比べる）
  ↓
transform() → apply_column_names()
  ↓
output/<KEY>_<YYYYMMDD_HHMMSS>.csv（UTF-8 BOM）へ書く
  ↓
結果を表示（クラス名・件数・判定・列数・列名・出力先）
```

**件数が不一致でも CSV は書く。** 試す道具なので中身を見たいから。

### 2.1 Python のコードから呼ぶ場合（`to_csv()`）

コマンド（`main.py`）とは別の入口。**管理表も接続設定も通さない。**

```
  ↓
レポートのクラス（またはモジュール）を受ける
  ↓
SOQL を得る（SoqlReport.soql()）
  ↓
先頭が未完成の印 → 例外で止める（bulk_query は呼ばない）
  ↓
渡された接続で bulk_query(soql)
  ↓
件数の比較（REPORT_ID があるときだけ。レポート API の RowCount と比べる）
  ↓
transform() → apply_column_names()
  ↓
output/<KEY>_<YYYYMMDD_HHMMSS>.csv（UTF-8 BOM）へ書く
  ↓
結果を表示（クラス名・件数・判定・列数・列名・出力先）
```

| 受け付けるもの | 意味 |
|---|---|
| レポートのクラス | そのレポートを 1 本実行する |
| モジュール | その中で定義された `SoqlReport` サブクラスがちょうど 1 つのとき、その 1 本を実行する |

- **接続は呼び出し側が開いたもの**を使う（開かないし閉じない）
- 接続を作らないので、`site_for()` も管理表も使わない
- 件数の比較に使うレポート ID は、レポート定義のクラス属性 `REPORT_ID`
  （無いときは「比較せず」＝判定は「比較できず」）

## 3. 入出力

| 種別 | 内容 | 場所 |
|---|---|---|
| 入力 | レポート定義（`.py`） | `config.ini` `[FILES] REPORTS_DIR` |
| 入力 | レポート定義（`.py`） | `reports/` パッケージ（`to_csv()` のとき。`REPORTS_DIR` とは別） |
| 入力 | レポート管理表（Excel） | `config.ini` `[FILES] MASTER_XLSX_PATH` |
| 出力 | 試した CSV | `config.ini` `[FILES] OUTPUT_DIR` |

管理表はシート `管理表`（comken の規約で実ファイルは `PY_管理表`）から、
**`ID` と `Salesforce URL` の 2 列だけ**読む。`--url` を指定したときは管理表を開かない。
`to_csv()` は管理表を **開かない**（接続は呼び出し側が開いたものを使う）。

---

## 4. 設定（config.ini）

| セクション | キー | 意味 |
|---|---|---|
| `[FILES]` | `DOWNLOADER_ROOT` | ダウンローダーのフォルダ（`src` の親）。`sys.path` の先頭に足す |
| `[FILES]` | `REPORTS_DIR` | 試すレポート定義（`.py`）を置くフォルダ |
| `[FILES]` | `MASTER_XLSX_PATH` | レポート管理表（Excel） |
| `[FILES]` | `OUTPUT_DIR` | 試した CSV の書き出し先 |

**4 つとも必須で、既定値の補完はしない。** `from comken import config` で直接読む
（`settings.py` のような自前の設定読み込みは作らない）。

## 5. 構成

```
main.py            エントリポイント（ログ初期化・エラー受け・終了コード）
config.ini         設定（.gitignore。初回実行時に example から作られる）
config.ini.example 設定の雛形
実行.bat            起動用（ターミナルから叩く。`pause` 無し＝無人実行向け）
認証情報の登録.bat   認証情報（ID・パスワード・client_secret）を DPAPI へ登録する画面
tester/
  paths.py          設定の読み取りとパスの解決
  downloader.py     ダウンローダーの部品の取り込み（sys.path の準備）
  reports.py        レポート定義（.py）の読み込み（ファイル単位・パッケージ単位）
  master.py         レポート管理表の読み取り
  run.py            1 本のレポートの実行（取得・比較・加工・CSV 書き出し・to_csv）
  cli.py            引数の解釈と終了コード
reports/            試すレポート定義（.py は git ignored。__init__.py だけ含める）
input/              レポート管理表（git ignored）
output/             試した CSV（git ignored）
tests/              テスト
docs/
  使い方.md         操作手順（非エンジニア向け）
  仕様書.md         この文書
  ERRORS.md         エラー対応
```

### ダウンローダーの部品は「コピーしない」

`SoqlReport` / `apply_column_names()` / `_fetch_report_total_count()` /
`INCOMPLETE_SOQL_MARKER` は、**ダウンローダーのものをそのまま import する**
（`tester/downloader.py`）。 コピーすると、ダウンローダーを直したときにこの道具
だけ古くなり、同じ SOQL でも「試した時」と「本番で動く時」で結果が変わる。

import を関数の中に置いているのは、ダウンローダーの場所が `config.ini` で決まるため。
モジュール読み込み時に import すると、`config.ini` が無い状態で `import tester` が
失敗し、`--help` やテストが動かなくなる。

### `reports` パッケージ

`reports/__init__.py` は、`reports/` の中のレポート定義（`.py`）を全部読み込んで、
名前（`report_1001` など）を `__all__` に載せる。 だから `from reports import *` で
モジュール済みの名前が取れる。 読み込みの規則:

- `_` で始まるファイル（`__init__.py` や雛形）は読み飛ばす
- Python の名前として書けないファイル名（`1001.py` など）は警告して読み飛ばす
  （`import` できないため。CLI の一覧には従来どおり出る）
- 壊れた `.py` はエラーにする（ファイル名と例外の型名だけを出す。例外の本文は出さない）
- 管理番号（`KEY`）の検査と重複検査は **しない**（使うとき＝`to_csv()` と CLI で検査する）

`reports/*.py` は git ignored だが、`reports/__init__.py` だけは git に含める
（`.gitignore` に `!reports/__init__.py` を足してある）。

## 6. 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功（件数が一致した／比較できなかった／比較なし） |
| 1 | 失敗（未完成・取得失敗・加工失敗・件数不一致） |
| 2 | 使い方の誤り（引数が違う・見つからない・管理表に無い） |

引数の書き方自体が間違っている場合は argparse が 2 で終了する（`main.py` と同じ）。

---

## 7. 実行方法

- 通常: ターミナルで `python main.py <管理番号>` を叩く（または `実行.bat <管理番号>`。
  `実行.bat` は `python main.py %*` なので引数をそのまま渡す）
- 一覧を出すだけ: `python main.py --list`（Salesforce にはつながらない）
- SOQL を見るだけ: `python main.py <管理番号> --show`（Salesforce にはつながらない）
- 動作確認: `main.py` の `with debug():` を外すと詳細ログが出る

---

## 8. ダウンローダーへ移す手順

1. 試した `.py` をダウンローダーの `src/soql_reports/reports/` へコピーする
   （ファイル名が `_` で始まると自動登録の対象外になる）
2. レポート管理表の、その管理番号の行の「SOQL」列を「○」にする

**この道具はダウンローダーへ何も置かない。** 上の 2 つは手作業で行う。
